## Findings and changes

### Fixed

1. **Vacay calendar days were mouse-only 28px `div` cells.** They could not be reached or activated by keyboard or assistive technology, and were too small to tap comfortably. Days are now labeled buttons, one date per month is in the tab order, arrow keys move between dates, blocked days announce their disabled state, and mobile cells are 44px tall. Decorative overlays use phrasing elements valid inside buttons.
2. **Journey screens displayed raw `journey.*` keys.** The English dictionary had no Journey entries. Added English UI strings for Journey overview, details, sharing, editing, contributors, and public pages.
3. **Collections search was too narrow on mobile.** Its input showed only a few placeholder letters beside the view controls. It now occupies a full-width row; the mobile capture checks the input width and viewport bounds.
4. **Three screenshot cases no longer matched the current UI or Playwright API.** Vacay details clicked through an open dialog, the poll check expected obsolete option text, and the photo mock called nonexistent `route.redirect()`. Updated those cases and verified them in the full capture.
5. **Dashboard travel statistics looked like zero during a failed or pending stats request.** Cached trip cards could remain visible while the dashboard showed zero trips, days, and distance. The metrics now display an em dash until stats load, and the desktop/mobile screenshot cases verify that trips remain visible during the failure state.
6. **Mobile navigation let page text show through its glass surface.** Raised the shared bottom bar's background opacity to keep its labels and surrounding content visually distinct; reviewed the updated Dashboard, Settings, and Trip Planner mobile screenshots.
7. **Client typecheck did not support `Array.at` in an untracked Atlas test.** Replaced the two test-only calls with equivalent indexing to match the existing ES2020 target.
8. **Atlas map features were unavailable on mobile.** The mobile route showed only the map and a compact stats strip; the Stats, Bucket List, and Wonders panel was hidden below `md`, leaving those views inaccessible. Reused the existing panel above the mobile navigation, constrained its grid to the viewport, and kept the stats row horizontally scrollable. The Bucket List form now shows its localized Month and Year defaults instead of unlabeled em dashes. Desktop and Pixel screenshot tests verify the views and that the form controls stay within the viewport and clear the bottom navigation.
9. **Trip Planner readiness hid most actionable checks.** On a populated 18-day trip, the mobile Plan sheet showed four checks followed by a non-interactive “+14 more”. Replaced that text with a keyboard-accessible show/hide button so travelers can inspect every warning without making the sheet longer by default.
10. **Trip Planner day dates overlapped their action buttons on mobile.** The expanded-readiness screenshot showed the corner-pinned day menu covering date labels. Reserved 36px on mobile day content while leaving desktop sizing intact.
11. **Journey synced-place summaries exposed `{count}` literally.** The desktop Journey detail capture showed “3 {count} places synced” in day headers. Both the timeline and linked-trip settings dialog now pass the count through the translation helper, and the Journey detail screenshot asserts “3 places synced”. Client typecheck passed; the focused Journey screenshot run passed 3 cases and the refreshed `client/e2e/.tmp/shots/JourneyDetail.png` confirms the visible text.
12. **Journey detail had an unnamed settings button in its hero.** The page’s other settings button already uses the localized `journey.settings.title`; applied that same accessible name to the hero button. The focused seeded browser case opens the settings dialog and verifies its linked-trip count; 3 screenshot-project cases passed.
13. **Journey GPX tracks were requested but never served or drawn.** Added an access-checked endpoint that reads valid `route_geometry` from linked trips, and connected those tracks to both Journey map renderers. The service test verifies owner/viewer access, excludes unlinked trips, drops elevation, and skips malformed geometry. The focused desktop/mobile capture checks the real empty response and uses a representative GPX line fixture; its refreshed `JourneyDetail.png` visibly shows the route across Japan. Client/server typechecks and the focused server unit test passed.
14. **Collections search controls had no accessible name and no-match results offered no recovery action.** Added localized names to both list and map-overlay searches, plus a 44px Clear filters action that resets search, status, category, and label filters. Desktop and Pixel captures now cover populated → no matches → restored places; the focused screenshot cases passed, client typecheck passed, and the light desktop/mobile and dark desktop empty-state screenshots were reviewed.
15. **Settings/Admin mobile navigation controls were below the 44px touch target guideline.** The shared `PageSidebar` used 36px open controls, 32px close controls, and 36px tab rows. Increased these to at least 44px. The Pixel 7 capture measures every target and verifies selecting a tab closes the drawer on both Settings and Admin; the focused screenshot run passed and both drawer screenshots were reviewed.
16. **The mobile Trip Planner’s nearby-category rail clipped its label and covered map controls.** The Pixel 7 screenshot showed the rail extending off the left edge and overlapping the compass/location buttons. Made the rail horizontally scrollable within a reserved lane and kept both map controls clear. The focused mobile screenshot case now asserts the rail and label stay within the viewport and the rail clears both buttons; 3 cases passed including setup and seed, and the refreshed `client/e2e/.tmp/shots/mobile/TripPlanner.png` was reviewed.
17. **Password recovery’s email label was not associated with its input, and the pending action said “Signing in…”** Connected the label, added reset-specific loading text and a polite status announcement. The delayed-submit Pixel 7 case checks the accessible label, pending status, disabled button, and success confirmation; 4 cases passed including setup and seed, and `PasswordResetSubmitting.png` was reviewed.
18. **Login and registration did not announce pending requests or expose request errors as alerts.** Added an accessible busy state and live loading status to the shared auth form, and alert semantics to its error messages. Delayed login and rejected-login/registration cases passed in the isolated Pixel 7 screenshot run (4 cases including setup); reviewed `LoginSubmitting.png`, `LoginRejected.png`, and `RegistrationRejected.png`.
